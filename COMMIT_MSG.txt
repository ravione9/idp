Stability: async error wrapper, non-fatal unhandledRejection, /diagz

PROBLEM
- /api/iga/* requests caused ERR_EMPTY_RESPONSE / ERR_CONNECTION_REFUSED
  in the browser. Root cause: Express 4 does not auto-catch errors from
  async route handlers. A rejected promise in iga.ts became an
  unhandledRejection, which the global handler in src/index.ts treated
  as fatal (process.exit(1)). The container kept crash-looping.

FIX
- src/utils/async-handler.ts wraps an async handler so it forwards errors
  to next(err), reaching the global error middleware (proper 500 JSON).
- All routes in src/api/iga.ts now use asyncHandler.
- process.on('unhandledRejection') in src/index.ts now logs only — does
  NOT exit. One bad query no longer kills the whole web server.
- uncaughtException still exits (those usually mean process state is
  corrupt and a restart is the safe choice).

DIAGNOSTICS
- New GET /diagz returns:
  - the rows of lilg_schema_migrations (which migrations are applied)
  - presence of each IGA table (applications, connectors, entitlements,
    access_requests, sod_policies, risk_scores, compliance_reports, ...)
  Use it to confirm migrations 003 + 004 actually applied on a server.
